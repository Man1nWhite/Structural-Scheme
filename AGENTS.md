# Инструкция для агентов

Проект полностью ведут агенты. Релизов, версий и changelog нет — не создавайте их.

## Что это

Генератор структурных схем АСУ ТП. На выходе — **один файл `index.html`**, который собирается из `src/`
командой `npm run build`: открывается двойным щелчком, работает без интернета и без остальных файлов
репозитория. Язык интерфейса, комментариев и тестов — русский.

## Структура

| Путь | Что внутри |
| --- | --- |
| `index.html` | **Сгенерирован** из `src/shell.html` командой `npm run build`. Руками не править — правки потеряются при следующей сборке. |
| `src/shell.html` | Каркас страницы: подключает стили и скрипты, больше ничего. Источник для сборки. |
| `src/core.js` | Вся логика без DOM: модель проекта, раскладка и трассировка, `toSvg`, `toDrawio`, сохранение/загрузка. |
| `src/app.js` | Интерфейс на React 18 + [htm](https://github.com/developit/htm) (шаблонные строки вместо JSX, Babel не нужен). |
| `src/styles.css` | **Сгенерирован** Tailwind CSS 3 из классов в `src/shell.html` и `src/app.js`. Руками не править. |
| `vendor/` | **Копии** React, ReactDOM и htm из `node_modules`. Руками не править. |
| `tests/` | `node:test`; `app.test.js` — сквозные тесты собранной страницы в jsdom, `routing.test.js` — свойства чертежа. |
| `scripts/` | `build.js` (сборка `index.html`), `vendor.js` (обновить `vendor/`), `serve.js` (локальный сервер). |

## Команды

```bash
npm ci              # один раз: зависимости для тестов и сборки
npm test            # все тесты; должны проходить перед каждым коммитом, ожидаемых падений нет
npm run build       # пересобрать index.html — обязательный шаг после любой правки src/
npm run build:css   # после добавления/удаления Tailwind-классов
npm run vendor      # после смены версий react/react-dom/htm в package.json
node scripts/benchmark-routing.js  # замер модели и SVG плотного проекта, без отрисовки браузером
npm start           # сервер на http://localhost:8000/ (0.0.0.0, порт — переменная PORT)
```

## Правила

- **`index.html` — артефакт сборки.** Правьте `src/*`, затем `npm run build`. `tests/repo.test.js` сравнивает
  закоммиченный `index.html` с результатом сборки: если файл устарел, тесты падают.
- **Размеры блоков считаются от содержимого.** Высота — `blockHeight()` по числу строк
  `blockLines()`, ширина АРМ — `ARM_W` (3/4 `BW`), узкий блок центрируется в своей колонке.
  Подпись и строки обрезаются по ширине (`nameText`, `fit` в `toSvg`): не возвращайте
  фиксированные `OP_H`/`RACK_H`/`NET_H`/`AUTO_H` и не переносите длину текста в константы —
  `tests/layout.test.js` сверяет высоту с числом строк, а `tests/render.test.js` — что подписи влезают.
- **Одна модель — все форматы.** `buildScheme(state)` считает всю геометрию и тексты; `toSvg` (предпросмотр,
  SVG, PNG, JPG) и `toDrawio` только рисуют эту модель. Новый элемент схемы добавляйте в модель и в **оба**
  рендера; `tests/render.test.js` сверяет, что подписи в SVG и Draw.io совпадают.
- **Трассировка основана на пользовательском `index backup.html`.** Точки выхода идут в порядке
  положения целей, входы — в порядке подходов, слоты зазоров распределяются отдельно по уровням,
  с пересчётом после добавления целей. `layoutWithRepair` сначала строит эту геометрию, затем
  устраняет совпавшие отрезки: сдвиг конца обычной связи на половину `EXIT_STEP`, выбор порядка
  каналов только при меньшем их числе, строгие ограничения встречных вертикалей, разнесение
  внутренних обходов. Для RS-485 допустим короткий ортогональный отвод вдоль грани, но не сдвиг
  самого конца. Из вариантов с наименьшим числом наложений выбирается самый ранний.
  Не возвращайте глобальное резервирование `seat()` без запроса. `tests/backup.test.js` фиксирует
  опорные маршруты; не меняйте эти пины ради исправления. `tests/routing.test.js` проверяет свойства
  чертежа отдельным оракулом в `tests/helpers.js`; не ослабляйте проверки и не добавляйте `todo`.
  После изменений трассировки запускайте оба набора, а также `layout` и `render`.
- **Новое поле проекта или элемента** — добавьте значение по умолчанию в `PROJECT_DEFAULTS` / `ITEM_DEFAULTS`
  в `src/core.js`. Иначе поле не переживёт сохранение и загрузку: `normalizeState` принимает только известные поля.
  Старые сохранения должны открываться; если формат меняется несовместимо, увеличьте `FORMAT_VERSION` и
  добавьте миграцию в `normalizeState`. Значения, влияющие на геометрию, ограничивайте при загрузке
  (`blocksPerRow` → `clampPerRow`), иначе чужие файлы растянут лист.
- **Ссылки между элементами** (`target`, `netTarget`, `rs485Target`) могут указывать на удалённые элементы —
  всегда разрешайте их через `makeResolvers`.
- **Связь сверху у шкафа автоматики** — поле `uplink`: «Витая пара», «Оптика» или `UPLINK_NONE`
  («Без связи»). Для «Без связи» линия к сетевому шкафу не строится, связь шкаф-шкаф от этого не зависит.
  Список для интерфейса — `AUTO_UPLINK_OPTIONS`; не заменяйте его на `AUTO_UPLINKS`.
- **RS-485 между шкафами** выходит из нижней грани справа — после стрелок DI/DO/AI/AO/RS-485 —
  а при входе в нижнюю грань встаёт слева, до стрелок (`cabEdge`, `cabLinkX` в `src/core.js`).
  Стрелки сигналов остаются на своих местах: иначе вертикаль совпадёт со стрелкой и будет читаться
  как ещё один сигнал. Не переносите эти концы в центр грани и не сдвигайте их при починке трассировки. `tests/backup.test.js` фиксирует точки,
  `tests/layout.test.js` проверяет их положение относительно стрелок.
- **Экспорт растровой картинки** ограничен размерами canvas: масштаб считает `rasterScale()`, а `toBlob`
  может вернуть `null`. Ошибки создания контекста, рисования и кодирования обязаны показать сообщение,
  а не молча ничего не сохранить (`src/app.js`). Ошибка чтения файла проекта тоже выводится пользователю.
- **Автосохранение не должно уничтожать нечитаемые данные.** До записи демо-проекта исходный текст
  сохраняется под `STORAGE_BACKUP_KEY`; интерфейс предлагает скачать копию и честно сообщает, если
  резервная запись не удалась. Скрытие предупреждения не удаляет копию. Проверяйте также более новый
  `FORMAT_VERSION` и отказ `localStorage.setItem`.
- **Количества** нормализуются через `toCount`: целые от 0 до `COUNT_MAX`. Пустое количество сигнала
  допускает `''`, чтобы не показывать число; `blocksPerRow` отдельно ограничивается `clampPerRow`.
  Идентификаторы из файла экранируются в XML-атрибутах Draw.io, а не подставляются как готовая разметка.
- **Доступность и переносы.** `Lbl` оборачивает поле в связанный `<label>`; поля строк таблиц получают
  `aria-label` с именем и номером элемента. Заголовки и примечания заранее переносит `wrapText` в общей
  модели; оба рендера используют одни строки. Подписи сигналов имеют белую обводку/подложку.
- **Интерфейс** пишется на htm: `` html`<${Comp} prop=${value}>…<//>` ``. JSX не работает.
- **Локальный сервер** запрещает выход из корня, скрытые пути и `node_modules`, в том числе через
  символические ссылки; некорректные URL не должны завершать процесс. Проверяйте `tests/serve.test.js`.
- **Без внешних ресурсов**: никаких CDN и `fetch` — `tests/repo.test.js` проверяет, что собранная страница
  не ссылается на внешние файлы и работает офлайн.
- Тесты проверяют поведение (результат `buildScheme`, `toSvg`, `toDrawio`, свойства чертежа, работу страницы),
  а не текст исходников. Исправили ошибку — добавьте тест, который её ловит.
- Изменили поведение или порядок работы — обновите `README.md` (для людей) и этот файл (для агентов).
- Переносы строк — LF (`.gitattributes`).
- CI (`.github/workflows/ci.yml`) запускает `npm ci && npm test` на Node.js 22 и 24 и отдельную задачу `npm audit` для каждого PR.
  Поддерживается Node.js 22+; обе версии CI должны быть зелёными. Не скрывайте падения тестов.

## npm audit

Все зависимости — `devDependencies`; в `index.html` попадает только `vendor/`. Проверяйте аудит целиком:
`npm audit --omit=dev` здесь не проверяет цепочку сборки, а `|| true` скрывает любой результат.
Для `postcss-selector-parser` используется совместимое исправление 6.1.5 через `overrides`; принимайте
изменения этой цепочки только после побайтового сравнения `src/styles.css` до и после `npm run build:css`.
Предупреждение braces GHSA-vfj7-8cjw-p6xm отозвано 23.10.2026; на 03.11.2026 аудит чистый.
Не делайте `npm audit fix --force` и не переходите на Tailwind 4 ради аудита: `@tailwindcss/cli` 4.3.3
тоже зависит от `@parcel/watcher` 2.5.1 и braces. React 18 и его UMD-сборки — часть архитектуры;
переход на React 19 требует отдельного решения об изменении сборки, а не простого обновления версии.

# Structural Scheme

Генератор структурных схем для АСУ ТП. Приложение позволяет настраивать операторные станции, серверные
стойки, сетевые шкафы и шкафы автоматики, а затем экспортировать результат в SVG, PNG, JPG или Draw.io.

Приложение — **один файл `index.html`**: открывается двойным щелчком, не требует установки, сборки в браузере
и доступа к интернету (библиотеки и стили встроены в файл).

## Запуск

1. Откройте `index.html` в современном браузере.
2. Настройте проект на вкладках **Проект**, **Операторная**, **Серверная** и **Шкафы автоматики**.
3. Используйте кнопки экспорта над предпросмотром схемы: **SVG**, **PNG**, **JPG**, **Draw.io**.

На вкладке **Шкафы автоматики** для каждого шкафа выбирается **связь сверху**: «Витая пара», «Оптика»
или «Без связи». «Без связи» нужна, когда шкаф не подключается к сети, а связывается только
с другим шкафом по RS-485.

Чтобы связать два шкафа, включите **RS-485 между** и выберите второй шкаф: линия выйдет из нижней
грани шкафа справа — после стрелок DI/DO/AI/AO/RS-485 — и войдёт в нижнюю грань второго шкафа
слева, перед стрелками. Связи появляются на схеме и во всех форматах экспорта.

### Размеры блоков

Блоки подстраиваются под содержимое: высота зависит от числа строк описания (чем меньше
контроллеров, модулей и опций включено, тем ниже блок), а блоки операторной — АРМ, принтеры
и панели — на четверть уже шкафов. Узкий блок стоит по центру своей колонки, общая сетка
схемы не меняется.

### Построение линий

За основу взята трассировка из `index backup.html`: выходы распределяются по положению целей,
входы — по порядку подходящих линий, обходы рядов — по межколоночным зазорам. Затем схема
проверяется на совпавшие участки и при необходимости уточняется: немного сдвигается конец
обычной связи, выбирается более компактный порядок каналов или разносятся внутренние обходы.
Если у RS-485 совпадают вертикали, добавляется короткий отвод, но закреплённая точка на шкафу
и стрелки сигналов не перемещаются. Выбирается вариант с наименьшим числом наложений; при равенстве
сохраняется более ранний вариант. Опорные маршруты backup закреплены в `tests/backup.test.js`.

Подписи сигналов имеют белую подложку. Длинные заголовки и примечания переносятся по словам;
высота заголовка и примечаний учитывается в размере листа. Эта геометрия и тексты используются
в предпросмотре и во всех форматах экспорта.

При необходимости страницу можно открыть через локальный сервер:

```bash
npm start   # http://localhost:8000/
```

Сервер не отдаёт скрытые файлы, `node_modules` и файлы вне корня, в том числе через
символические ссылки; некорректные адреса не прерывают его работу.

Для воспроизводимого замера построения плотной схемы и SVG (без времени отрисовки браузером)
используйте `node scripts/benchmark-routing.js`. Он выполняет прогрев и 300 измерений проекта
с 12 блоками в ряду и примерно 30 связями; результаты зависят от машины и не являются порогом CI.

## Сохранение проекта

- Все изменения автоматически сохраняются в браузере и восстанавливаются при следующем открытии страницы.
- Если сохранение повреждено или создано в более новом формате, открывается пример с предупреждением.
  Исходный текст откладывается под отдельным ключом хранилища; кнопка **Скачать копию** сохраняет его без изменений.
  При нехватке места в хранилище копию всё равно можно скачать. Для важных проектов используйте **Сохранить проект**:
  файловый экспорт не зависит от общего хранилища страниц `file://` и настроек браузера.
- На вкладке **Проект** кнопка **Сохранить проект** скачивает файл `.json`, а **Открыть проект** загружает его
  обратно — так проект можно перенести на другой компьютер или передать коллеге.
- **Начать заново** заменяет текущий проект демонстрационным примером (после подтверждения).

## Разработка

Требуется Node.js 22 или новее. CI проверяет Node.js 22 и 24 и отдельно запускает полный `npm audit`; все проверки должны проходить, ожидаемых падений нет. `index.html` — **собранный файл**: правьте исходники в `src/` и пересобирайте.

```bash
npm ci            # зависимости для тестов, сборки страницы и CSS
npm test          # все тесты, включая сквозные в jsdom и проверку свежести сборки
npm run build     # собрать index.html из src/ (обязательно после правок)
npm run build:css # пересобрать src/styles.css после изменения Tailwind-классов
npm run vendor    # обновить vendor/ после смены версий react / react-dom / htm
npm start         # локальный сервер: http://localhost:8000/
```

### Зависимости и аудит

Все npm-зависимости относятся к разработке и тестам; в автономную страницу встраивается только
`vendor/` и исходный код. Tailwind CSS 3 и React 18 сохранены: смена мажорной версии не является
исправлением аудита, а React 19 уже не поставляет используемые здесь UMD-сборки.

Для `postcss-selector-parser` закреплено исправление **6.1.5** через `overrides`: эта ветка совместима
с Tailwind 3, а пересборка CSS проверена на побайтовое совпадение. На 3 ноября 2026 года `npm audit`
не сообщает уязвимостей. Упомянутое ранее предупреждение braces
[GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm) отозвано 23 октября 2026 года;
переход на Tailwind 4 ради него не нужен. Новые предупреждения следует проверять целиком, без
`--omit=dev`, оценивая их применимость к локальной сборке. Не применяйте `npm audit fix --force` вслепую.

Устройство проекта и правила внесения изменений описаны в [AGENTS.md](AGENTS.md).
